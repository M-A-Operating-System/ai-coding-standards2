## Original issue (snapshot before PRD rewrite)

**Original title:** [#142 - 5/6] Collapse pause/stop into single _check_controls() guard

**Original body:**

## Context

Part 5 of 6 — implements the fifth phase of the orchestrator simplification described in #142.

## Problem Statement

The orchestrator currently has separate `_is_paused()` and `_is_stopped()` checks scattered at multiple call sites. These should be collapsed into a single `_check_controls(repo) -> Literal["run", "pause", "stop"]` function called once per work item at the top of `process_work_item()`. This eliminates duplicated guard logic and makes control flow explicit.

## Acceptance Criteria

- [ ] `_check_controls(repo)` function added; reads the repository-level pause/stop signals and returns one of `"run"`, `"pause"`, or `"stop"`.
- [ ] All existing `_is_paused()` / `_is_stopped()` call sites removed and replaced with a single call to `_check_controls()` at the entry of `process_work_item()`.
- [ ] `_is_paused()` and `_is_stopped()` functions removed from the orchestrator.
- [ ] Existing CI passes; no regressions in control-flow behaviour.

## Dependencies

None — can be delivered independently.
